# Implementation Decision Register (build-time)

Decisions taken by the engineering team during implementation. Business decisions (DEC-001…067) remain in the
documentation package (Doc 17). Each IMPL decision references the DEC it adapts.

| ID | Decision | Reason | Alternatives considered | Impact | Source | Approval |
|---|---|---|---|---|---|---|
| IMPL-001 | Deliver the documented functionality **without paid plugins**: no Elementor Pro, ACF Pro or WPML. `momos-core` provides a code-registered field layer (native meta boxes, fixed keys), its own multilingual layer, SEO/hreflang/sitemap/JSON-LD, TOTP 2FA, login throttling, SMTP transport and activity logging. A custom classic theme `momos` renders all templates from the design system (Doc 08). | Purchasing licences is an external financial action outside the build authorization; wordpress.org (plugin downloads) is unreachable from the build environment; the documented behaviour (Doc 04/09/10) is fully implementable with WordPress core APIs. Also removes ≈US$250/yr licence cost and 12 of 14 plugins (smaller attack surface, LC-001). | (a) Wait for licences — blocks the whole build. (b) Polylang/Elementor free from GitHub — unbuildable here and still need Pro features. | Adapts DEC-005/006/007/031/032 and TRD §1.2–1.3. Data stays in standard post/term meta and the 8 custom tables (DEC-009), so a later move to ACF/WPML remains possible. Theme declares Elementor support so pages can be edited with Elementor if the owner installs it. | TRD §1, SDD §2 | Owner/CTO to ratify (reversible) |
| IMPL-002 | Multilingual storage: Japanese source values live in the native post fields/meta; each other language is stored per entity as meta `_momos_i18n_{lang}` (JSON of translatable fields) with `_momos_i18n_status_{lang}` ∈ `missing, draft, needs_review, approved`. An item is shown in a language only when its status there is `approved` (DEC-027 "no mixed-language fallback"). Language-independent fields (price, allergens, hours, coordinates) are stored once — equivalent to WPML/ACFML "Copy" mode. URL: ja at root, `/en/ /ar/ /ur/ /hi/ /bn/` prefixes (DEC-003). Slugs are shared (romaji) across languages. | Same guarantees as WPML for this content model with far less complexity; no sync problems for shared fields. | WPML-style one post per language | Translator role edits translation fields only. | DEC-002/003/005/027 | CTO |
| IMPL-003 | Languages are publicly enabled by a per-language setting (language launch gate, DEC-002). On dev/staging all six are enabled for QA; production defaults ja+en until native review sign-off is recorded. UI strings for ar/ur/hi/bn are delivered as **draft translations requiring native review** (DEC-027). | DEC-002/027 | — | Release gate GATE-04 per language | DEC-002 | Owner |
| IMPL-004 | Optional free plugins documented in TRD (FluentSMTP, Wordfence, Simple History, UpdraftPlus, LiteSpeed Cache, Rank Math) are **not required**; their Phase 1 functions are covered in momos-core or host services. Host WAF/CDN and off-site backup storage remain operational prerequisites. | IMPL-001 | Install them in production | Plugin count 1 (+ theme) ≤ 15 cap | TRD §1.3 | CTO |
| IMPL-005 | UI baseline repository UI-001 (`marufshehzad/momos-cafe`) is attached read-only in the build environment and used as the layout/visual reference together with Doc 08 / 08A. Because it contains the client's real name, phone and branding and this repository is public, **no image, logo, phone number, address or client identity is copied from it**: the theme uses an outlined provisional wordmark (DEC-046/067) and self-drawn icons; demo photos are imported from the local UI-001 checkout into the media library at seed time only (never committed). | Repository privacy (UI-001 README) vs. public target repository | Copy assets into the theme | Final logo/photos are supplied through Brand settings and the media library before launch | DEC-046/047/057/067 | UX lead (side-by-side review open) |
| IMPL-006 | Consent version stored on new reservations is the version **explicitly activated** by Head Office (Settings or `wp momos privacy consent activate`); until one is activated reservations store `unversioned`. Version keys use the Doc 11 format `PP1.0-RP1.0` (≤ 20 characters, validated, never truncated). The TRD example `PP-2026-11-v1|RP-2026-11-v1` (27 chars) does not fit `varchar(20)`. | Activation is a legal act (counsel-approved texts); an automatic switch on a migration date could record a version whose text was never published. SCR-A19 warns when the registry's latest version differs from the active one. | Auto-apply the latest registry row | Owner/counsel must activate the launch version before go-live (launch checklist). | Doc 11, TRD API-02, reservation.md §2.2 | Owner/counsel |
| IMPL-007 | Language launch gate requires **every customer-facing catalog string in that language to be approved** (per-key review status), in addition to the LCCS content check. All shipped catalog strings start as `draft`; translators/reviewers approve them in Momo's → Strings. Already-enabled languages are not switched off automatically. | content-strings §3.2 + DEC-027 (no unreviewed customer text). | Gate on content only | Production launch: ja is source; en must be approved by a reviewer before it can be enabled; ar/ur/hi/bn after native review (GATE-04). | DEC-002/027 | Owner |
| IMPL-008 | `X-Robots-Tag` ownership: Security headers own private result pages (C10/C11) and staging; the SEO module owns indexability variants (filters, hidden language, TEST branch, 404) and the non-production header. Both send the same value; the SEO header replaces rather than appends. | Two modules set the same header. | Single module | — | i18n-seo-analytics §9.3, SDD §6.11 | CTO |
| IMPL-009 | Translation source hash ignores empty source fields, so adding a new optional translatable field (e.g. SEO description, FAQ list) never marks existing approvals outdated. Clearing a source field therefore does not flag translations either (editors are expected to clear the translation too). | SEO and Content added fields after translations were approved. | One-off re-hash migration per new field | Formula changed once before launch; no production data affected. | IMPL-002 | CTO |
| IMPL-010 | SEO capabilities `momo_manage_redirects` (SA, HO) and `momo_edit_seo_meta` (SA, HO, MM, CE) added to the role table (no TRD row). | SEO module needs dedicated caps. | Map to brand/all-branches caps | Roles re-sync automatically (signature). | i18n-seo-analytics §7 | CTO |
